Документация

Описание относится к версии 4.0.51. Если вы ещё не установили программу, начните со страницы загрузки.

Быстрый старт

  1. Установите программу и запустите её.
  2. Выберите источник заметок — облачный Microsoft Graph или классический OneNote на этом компьютере.
  3. Отметьте тетради, с которыми хотите работать.
  4. Запустите первую синхронизацию и дождитесь её завершения.
  5. Пользуйтесь поиском, переходите от библейской ссылки к заметкам и обратно.
Первая синхронизация — самая долгая: содержимое каждой страницы скачивается один раз. Дальнейшие запуски проверяют только изменившиеся разделы.

Источник заметок

BibleNote наполняет локальный кэш одним из двух способов. Оба дают одинаковый результат для поиска, разбора библейских ссылок и читалки.

Microsoft Graph (облако)

Работает без установленного OneNote и требует входа в учётную запись Microsoft — личную или рабочую. Программа использует собственную регистрацию приложения, поэтому создавать что-либо в Azure и вводить Client ID не нужно.

Запрашиваются только разрешения на чтение:

  • Notes.Read.All — чтение ваших и общих тетрадей OneNote;
  • User.Read — определение учётной записи, под которой выполнен вход;
  • offline_access — сохранение входа между запусками.

Классический OneNote на этом компьютере

Читает тетради, открытые в настольном OneNote, через его COM-интерфейс. Вход в учётную запись Microsoft и регистрация в Azure не нужны. Режим доступен только в Windows.

Идентификаторы объектов в Graph и в классическом OneNote разные. После переключения источника на уже наполненном кэше выполните его полное пересоздание — мастер настройки замечает такой переход и предлагает это сам.

Синхронизация

Полная и инкрементальная

Полная синхронизация обходит выбранные тетради целиком. Инкрементальная опирается на отметки времени разделов: OneNote иногда не обновляет дату изменения страницы после правки текста, поэтому дата страницы считается только подсказкой. Когда меняется отметка раздела, содержимое его страниц скачивается заново и сравнивается с сохранённым.

Каждый инкрементальный запуск дополнительно обновляет несколько недавно открывавшихся страниц и несколько самых давно загруженных — это скользящая страховка на случай пропущенных изменений. Прогресс сохраняется, поэтому прерванную синхронизацию можно продолжить.

Точечное обновление

У каждой тетради, раздела и страницы в дереве есть действие ↻. Оно повторяет текущие настройки синхронизации, но ограничивает обход выбранным элементом. У открытой страницы есть отдельная кнопка синхронизации. Обновление одной страницы не помечает её раздел полностью просканированным.

Ограничения скорости Microsoft Graph

Все параллельные загрузки используют общий ограничитель частоты запросов. Если Graph отвечает кодом 429, программа соблюдает заголовок Retry-After, приостанавливает работу и повторяет попытку с нарастающей задержкой. При частых ограничениях интервал между запросами увеличивается автоматически, а после успешных ответов постепенно возвращается к обычному.

Исходный HTML страниц

Текст страниц кэшируется всегда, исходный HTML — по желанию. Для больших коллекций его лучше не хранить. Чтобы получить HTML одной страницы, включите соответствующую настройку и обновите страницу действием ↻: после этого у неё появится кнопка «Показать HTML». Такой HTML открывается в изолированном фрейме.

Состояние разделов

  • пустая — OneNote вернул полный список страниц, и он пуст;
  • не загружена — раздел ещё не сканировался;
  • N · частично — список страниц оборвался из-за ограничения или прерывания;
  • число — раздел просканирован полностью.

Вложенные группы разделов обходятся рекурсивно, а путь группы показывается в дереве перед названием раздела.

Журнал загрузки

Панель «Журнал загрузки» показывает состояние страниц по выбранным тетрадям: загруженные за последнюю синхронизацию, все загруженные, оставшиеся без содержимого, ошибки Microsoft Graph с текстом сообщения или вообще все страницы кэша. Большие списки разбиваются на страницы.

Поиск и навигация

Дерево тетрадей, разделов и страниц подгружается по мере раскрытия. Полнотекстовый поиск использует индекс FTS5 по заголовку, тексту страницы, названию тетради и раздела и подсвечивает совпадения.

Набор тетрадей, участвующих в показе, поиске и синхронизации, выбирается отдельно и запоминается. Тетради можно переименовывать локально: значок карандаша задаёт отображаемое имя, которое хранится в базе и не меняет название в самом OneNote. Исходное название возвращается в том же окне.

Оформление переключается тремя темами: «A · Тёплая», «B · Светлая» и «C · Тёмная».

Библейские ссылки и параллельные места

При включённом разборе ссылок содержимое страниц передаётся локальному сервису BibleNote, а найденные ссылки сохраняются с точностью до абзаца. Дополнительно вычисляются взвешенные связи между ссылками, стоящими в одном абзаце и в следующих за ним, — на них опирается подбор параллельных мест и индекс параллельности.

Что это даёт при работе:

  • по любой ссылке можно найти все страницы заметок, где она встречается;
  • для ссылки показываются параллельные ссылки, ранжированные по близости и структуре записей;
  • от ссылки можно перейти к её тексту, к контексту в заметке или открыть место в читалке.

Разбор можно повторить для уже сохранённых страниц, не скачивая их содержимое заново.

Индуктивное изучение

Читалка открывает главу в основном переводе и позволяет сравнить её ещё с двумя. В режиме разметки выделенное слово или фразу можно отметить смыслом: ключевое слово, Бог, Христос, Дух Святой, время, место, сравнение, противопоставление, вывод, повеление. Отдельное действие применяет тот же стиль ко всем точным совпадениям в открытой главе. Свои стили ключевых слов добавляются из той же панели.

Панель «Индуктивные наблюдения» перечисляет разметку в порядке стихов, позволяет переходить к отметкам, снимать их, добавлять комментарии и отменять последнее действие. Разметку главы можно выгрузить в JSON и загрузить обратно.

Каждая отметка привязывается к переводу, каноническому месту в тексте, смещениям символов, самой выделенной цитате и ближайшему контексту — поэтому она не теряется при переоткрытии главы.

Хранение данных

  • ~/BibleNote/onenote-cache.sqlite — кэш тетрадей: метаданные, текст страниц, при необходимости исходный HTML, полнотекстовый индекс и результаты разбора библейских ссылок. Этот файл одноразовый: его можно удалить и собрать заново.
  • ~/BibleNote/biblenote-user.sqlite — ваша индуктивная разметка и палитры стилей. Хранится отдельно и переживает полное пересоздание кэша.
  • ~/BibleNote/msal-cache.json — сохранённый вход Microsoft при работе через Graph.

Резервная копия сводится к копированию этих файлов. Программа работает с OneNote только на чтение и не изменяет ваши тетради.

MCP-сервер для ИИ-агентов

BibleNote содержит сервер Model Context Protocol, который отдаёт локальный кэш совместимым ассистентам. Сервер работает только на чтение.

Инструменты по кэшу: состояние кэша, запуск синхронизации, поиск, чтение сохранённой страницы, списки тетрадей и разделов. Отдельно доступны поиск страниц по библейской ссылке и подбор параллельных ссылок. Есть и прямые обращения к Microsoft Graph для быстрых проверок: списки тетрадей и разделов, недавние страницы, поиск по заголовку и чтение страницы.

Пример настройки для клиента, читающего конфигурацию в формате TOML:

[mcp_servers.onenote]
command = "node"
args = ["C:/путь/к/BibleNote/dist/server.js"]
startup_timeout_sec = 20
tool_timeout_sec = 120

Ассистент получает доступ к тексту ваших заметок, поэтому подключайте сервер только к тем клиентам, которым доверяете.

Надстройка ленты OneNote

В Windows программа находит установленные версии классического OneNote и может зарегистрировать для текущего пользователя совместимую надстройку — для Office 2010, 2013 или 2016. После изменения настройки OneNote нужно перезапустить.

Вкладка на ленте даёт полную синхронизацию текущей страницы, быстрый разбор ссылок через COM и команду открытия BibleNote. В сборках для macOS этой возможности нет.

Командная строка

Тем, кто работает с исходным кодом, доступны отдельные команды синхронизации и обслуживания кэша: полная и инкрементальная синхронизация, ограничение обхода тетрадью, разделом или страницей, повторный разбор библейских ссылок, обновление давно не загружавшихся страниц, изменение параллельности запросов и путь к произвольному файлу базы.

Полный список параметров с примерами — в файле Web/README.md репозитория.

Частые вопросы

Программа меняет мои заметки?

Нет. Доступ к OneNote запрашивается только на чтение, а всё созданное вами внутри BibleNote — разметка, комментарии, локальные названия тетрадей — хранится в отдельных локальных файлах.

Синхронизация идёт очень долго

Это ожидаемо для первого запуска: содержимое каждой страницы скачивается один раз. Ускорить его нельзя — Microsoft Graph ограничивает частоту запросов. Дальнейшие запуски заметно быстрее.

Я переключил источник заметок, и дерево опустело

Graph и классический OneNote используют разные идентификаторы объектов. Пересоздайте локальный кэш заново.

Нужен ли интернет?

Только для синхронизации через Microsoft Graph. Поиск, чтение и разметка работают с локальными файлами.

Windows предупреждает о неизвестном издателе

Сборки пока не подписаны сертификатом. Проверьте контрольную сумму файла и продолжите установку.
